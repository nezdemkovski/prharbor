# Подгрузка строк при прокрутке — 2026-10-05

По просьбе пользователя PR Harbor теперь создаёт тяжёлые SwiftUI-строки по мере приближения к ним при скролле. Данные всех PR остаются в текущем persistent cache и в модели, поэтому обычный поиск, вкладки, сортировка и счётчики охватывают всю очередь. Сетевые запросы GitHub и их пагинация этим изменением не меняются.

## Реализация

`TimelineNativeScrollView` использует прозрачный стандартный AppKit `NSScrollView`. Его документ хранит полную высоту списка и заранее вычисленные координаты строк. Изменение clip bounds не публикует SwiftUI state и не перестраивает весь Panel.

- Диапазон рендеринга включает viewport и запас 240 pt с каждой стороны; границы округляются до пакетов по шесть строк.
- Уже подготовленные строки внутри диапазона сохраняют свои hosts. Удалённые hosts повторно используются; вне диапазона остаётся не более шести запасных hosts.
- Подготовка тяжёлой строки выполняется по одной за интервал 16 ms, с приоритетом видимых строк. Простой AppKit placeholder сразу показывает заголовок, вторую строку и занимает ровно ту же высоту. Клик по нему выполняет обычное действие строки.
- При переключении вкладки, изменении фильтра, данных или selection видимые строки подготавливаются синхронно в том же обновлении. Scroll position устанавливается сразу и уточняется после изменения размера панели. Это убирает промежуточный пустой кадр и постепенную замену заглушек при смене таба; очередь 16 ms остаётся для скролла и подготовки запаса вне viewport.
- Быстрый переход отменяет очередь предыдущего диапазона. Generation и cancellation guards не дают поздно подготовленным строкам вернуться в удалённый диапазон.
- Рендеринг больше не переключается на SwiftUI LazyVStack при превышении 120 PR: виртуализированный AppKit-путь используется для всех обычных размеров очереди.
- Внешняя высота панели и длина scrollbar остаются стабильными. При изменении данных сохраняется верхняя строка; выбор клавиатурой прокручивает и подгружает нужную строку.
- `TimelinePresentedRow` сравнивает содержимое и параметры отображения, сохраняя неизменившийся render tree при обновлениях. Цветовая схема, hover, brush, контекстные меню и исходные SwiftUI-компоненты сохранены.

Единица виртуализации — строка представления: заголовок репозитория, обычный PR или блок стека. Очень большой раскрытый стек пока остаётся одним блоком; его слои не виртуализируются отдельно.

## Проверка

Полный Debug test run: **79 tests / 14 suites passed**, 16.301 s. Лог: `/tmp/prharbor-virtual-scroll-final-test.log`.

Проверены повторная прокрутка 68 fixture PR вверх/вниз, стабильность размеров панели, завершение подготовки видимого диапазона, ограничение количества retained hosts, координаты 1000 строк, фильтрация до одной строки/пустого результата, отмена подготовки после резкого перехода и выбор невидимой строки клавиатурной selection. Fixtures включают группы репозиториев и небольшие стеки. Light/dark snapshots визуально проверены; графика исходного таймлайна сохранена.

Программный benchmark на 68 fixture PR, 90 изменений clip bounds (Debug):

| Рендеринг | Median layout, ms | p95, ms | Maximum, ms |
| --- | ---: | ---: | ---: |
| SwiftUI lazy | 7.57 | 17.14 | 46.89 |
| SwiftUI eager | 9.80 | 15.97 | 19.16 |
| AppKit с подгрузкой | 1.06 | 11.37 | 14.13 |

Это измерение синхронной прокрутки/раскладки тестового окна. Оно не включает всю стоимость подготовки в последующих интервалах, не измеряет GPU/FPS и не подтверждает плавность физического трекпада на реальных PR. Live-панель недоступна инструменту при закрытом popover; подтверждение реального быстрого скролла остаётся за пользователем.

Release и Debug сборки прошли. Логи: `/tmp/prharbor-virtual-scroll-release-build.log`, `/tmp/prharbor-virtual-scroll-debug-build.log`. Обновляется Release bundle `build/StatusMenu/PRHarbor.app` и стандартный Xcode Debug product. Подпись ad hoc с исходными sandbox/network-client entitlements проверяется отдельно после сборки. Org access, gh authentication и внешние PR не менялись.

## Исправление мигания вкладок

Причина регрессии: прежний `configure` очищал список видимых строк, а `updateNSView` откладывал позиционирование и всю подготовку на следующий main-loop callback. После этого видимые hosts создавались с интервалом 16 ms. Результат смены вкладки несколько кадров показывал заглушки.

Теперь `updateNSView` сразу позиционирует viewport и подготавливает все его строки с раскладкой hosting views. Уже готовые строки сохраняются. После раскладки панели видимый диапазон проверяется ещё раз, чтобы переход с короткого списка на длинный также показывал готовые строки. Обычная прокрутка по-прежнему использует отменяемую постепенную подготовку.

Полный набор после исправления: **81 tests / 14 suites passed**, 17.381 s; `/tmp/prharbor-tab-flicker-test.log`. Два новых regression tests проверяют пять быстрых замен табов через реальный `NSHostingController` без ожидания асинхронной очереди и переходы между непересекающимися результатами, включая рост viewport после короткого списка. Visible IDs должны быть подготовлены в том же layout/update. Тест прокрутки 68 fixture PR снова прошёл: native median 1.10 ms / p95 10.74 ms / max 13.53 ms (с теми же ограничениями программного benchmark выше). Физическая прокрутка и видеозапись live-панели не проверены этими тестами.

Сборки исправления: `/tmp/prharbor-tab-flicker-release-build.log` и `/tmp/prharbor-tab-flicker-debug-build.log`.
